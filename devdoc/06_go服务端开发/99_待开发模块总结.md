### 2026-09-05 会话修复内容

0. **编译错误修复（本轮起点）**：logger.Error → ErrorField 签名、models.Role 补
   UID/RoleID/DistName/Fatigue/MaxFatigue 字段、成就 handler 签名改
   proto.Message、register.go 补 10700/10701/10704/10706 成就消息注册。
1. **TCP 消息链路接通**（根因修复）：`server/server.go` 原使用 `BinaryCodec` +
   `BasicTCPHandler`（纯字节 echo），ProtoCodec 与 MessageDispatcher 从未接入 TCP。
   现改为 ProtoCodec + 全量消息注册 + 全量 handler 注册 + 分发器。
2. **全局编码器缺失**（组队 EOF 根因）：`Session.WriteResponse` 依赖全局
   `encoderInstance`，此前从未 `SetEncoderInstance`，所有 handler 响应发送静默失败，
   客户端表现为连接 EOF。已在 `server.NewServer` 与测试中设置。
3. **消息类型注册补齐**：`message_registry.go` 原只注册到 10007 公会模块，
   收到 PK/组队/冒险消息解码直接报「unknown message type」并断连。已补齐
   PK(10008, 18 个)、组队(10009, 17 个)、冒险(17201, 15 个)请求类型。
4. **adventure_service 改造**：由 `internal/db`（MySQL 直连）改为委托
   `store.Store`（双驱动），与成就/组队服务架构统一。
5. **pk_service 接线**：`serve.go` 在 MySQL 驱动下创建遗留 DB 并初始化 PK 服务。
6. **端到端链路测试**：新增 `tests/network_link_test.go`，验证真实
   TCPServer + ProtoCodec + dispatcher + handler 全链路收发（登录请求→响应），
   以及 12 个模块 handler 注册与编解码往返。

## TCP 全链路（2026-09-06）

### 背景与缺口

12 个 `*tcp_test.go` 套件长期存在以下问题：
- TCP 集成测试以文本命令发送（`"CMD:"+protojson`，2 字节大端长度前缀），但服务端 `ProtoCodec.Decode` 只支持二进制封包 `[2字节长度][2字节module][2字节cmd][protobuf]`，协议不匹配导致所有 TCP 测试无法真正打通；
- 测试端口硬编码 9000（Windows 不可绑定），实际服务监听 9500，测试连不上真实服务。

### 实装内容

1. **codec 文本命令兼容模式**（`internal/network/codec.go` + 新增 `internal/network/text_commands.go`）：
   - Decode 改为一次性读取长度+消息体后，按「module/cmd 是否已注册」判别二进制/文本，不再依赖首字节探测（长度 <256 时首字节为 0x00 不可靠）；
   - 文本格式 `"COMMAND:JSON"` → 通过 `textCommandMeta` 映射到 (module, cmd) → protojson 宽松解析（`DiscardUnknown`，mock JSON 中测试自定义字段不导致失败）；
   - 命令映射表覆盖 90+ 命令（auth/role/bag/dungeon/chat/shop/quest/guild/pk/party/achievement/auction）。
2. **TCP 测试端口可配置**：新增 `tests/tcp_port.go`（`tcpTestPort()`，默认 9000，环境变量 `DNF_TCP_PORT` 覆盖）；12 个 `*tcp_test.go` 的 `s.serverPort = 9000` 全部替换。
